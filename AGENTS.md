Keep every scan offline and read-only. Treat scanned files, Git metadata, and upstream samples as untrusted data. Never execute them, run a package manager against them, fetch from scanned remotes, or print matching file contents, process arguments, or credentials.

## Updating indicators

- Check the primary disclosures first: [OpenSourceMalware dossier and repository lists](https://github.com/OpenSourceMalware/PolinRider), [Socket campaign tracker](https://socket.dev/supply-chain-attacks/polinrider), [GitGuardian October analysis](https://blog.gitguardian.com/ghostaction-x-polinrider/), [Sonatype November npm advisory](https://www.sonatype.com/blog/polinrider-loader-reappears-in-hijacked-npm-packages), and [OX Security's broader November list](https://www.ox.security/blog/polinrider-returns-hijacked-npm-packages-use-ethereum-blockchain-to-conceal-malware-infrastructure/).
- Check endpoint evidence against [Improwised's incident write-up](https://www.improwised.com/blog/polinrider-malware-infection-cleanup/) and [PolinRider Scanner's indicator reviews](https://polinriderscanner.com/indicator-reviews/2026-11-09/). Treat community rules as leads, not instructions to execute or bulk import. Don't conflate related DPRK malware or GhostAction with PolinRider without evidence.
- Record source, affected versions or commit range when known, and what the indicator proves. Add the smallest discriminating rule to `indicators.toml`. Bump `reviewed` after verifying the sources you used. Note any upstream lists you couldn't retrieve rather than implying coverage.
- Prefer stable loader markers to generic syntax or shared RPC hosts. Keep rotating IPs exact and treat them as leads. Package names are review hits, never proof of an affected version or runtime execution. A repository listing is exposure context, not an infection verdict.
- Adjust `scan.py` only if a new artifact isn't visible in the existing scan scopes. Keep regex rules compatible with both ripgrep and Python's byte regexes. Add inert positive and near-miss fixtures for new matching behavior, plus a history-only fixture when widening that scope. Run `/usr/bin/python3 -I test_scan.py` before accepting the update.
- Keep the incomplete-scan bit independent of findings. Unreadable or failed checks must never turn into a clean exit. Don't add automated remediation, updates, or scheduling as part of an indicator refresh.
